# Zebra — платформа онлайн-обучения

Курсы состоят из модулей, модуль — из упорядоченных шагов. Шаг — это теория
или задание: одиночный выбор, множественный выбор, свободный ответ
(с файлами) или программирование на Python с проверкой тестами.

- **Ученик** проходит опубликованные курсы и отправляет решения.
- **Куратор** проверяет решения учеников своей группы.
- **Администратор** пишет курсы, управляет группами и ролями.

| Часть | Технологии |
|---|---|
| Бэкенд (`backend/`) | Python 3.12, FastAPI, SQLAlchemy (async), PostgreSQL, Alembic |
| Фронтенд (`frontend/`) | Vue 3, Pinia, Vite |
| Файлы | S3-совместимое хранилище (SeaweedFS), загрузка по presigned URL |
| Проверка кода | Judge0 1.13 (песочница isolate), воркер с очередью в Postgres |
| Прод | Docker Compose, Caddy (HTTPS от Let's Encrypt) |

Правила разработки для людей и ИИ-агентов — в [AGENTS.md](AGENTS.md).

## Типы заданий

Шаг курса создаётся запросом `POST /api/admin/modules/{id}/steps` с полем
`payload`: `type`, `max_score` (0–1000, по умолчанию 1), `content` (что видит
ученик), `answer_key` (правильный ответ, ученику не отдаётся) и `settings`.
Точные схемы всех типов — в `/docs` (`*Payload`).

| Тип (`type`) | Что это | Ответ ученика | Проверка (`settings.grading`) |
|---|---|---|---|
| `theory` | Теория (rich text) | пустой `{}` — отметка «прочитано» | `none`; балл всегда 0 |
| `single_choice` | Один верный вариант | `{"option_id": "<uuid>"}` | `auto` |
| `multiple_choice` | Несколько верных вариантов | `{"option_ids": ["<uuid>", ...]}` | `auto` |
| `free_text` | Свободный ответ: текст и/или файлы | `{"text": "...", "files": [id, ...]}` | `manual` — куратор |
| `programming` | Программа на Python 3 | `{"code": "..."}` | `tests`, `tests_and_review` или `manual` |

**Общие настройки всех заданий** (`settings`):

- `max_attempts` — число попыток (по умолчанию без ограничений). Новое
  решение можно отправить, пока предыдущее не на проверке, остались попытки и
  не набран максимальный балл; в зачёт идёт лучший балл.
- `show_answer` — когда ученик может посмотреть правильный ответ:
  `never` (по умолчанию), `after_wrong`, `after_attempts_exhausted`,
  `after_solved`.

**`theory`** — `content.body`: текст в формате TipTap/ProseMirror JSON.

**`single_choice` / `multiple_choice`**

- `content`: `question` (rich text), `options` — от 2 до 50 вариантов
  `{"id": "<uuid>", "text": "..."}`. Постоянные `id` позволяют менять порядок
  вариантов, не ломая правильный ответ.
- `answer_key`: `{"correct": "<uuid>"}` / `{"correct": ["<uuid>", ...]}`.
- `multiple_choice`, `settings.scoring`: `all_or_nothing` (по умолчанию) или
  `partial` — балл пропорционален `(верно выбранные − ошибочно выбранные) /
  число верных`, не меньше 0; выбрать всё подряд не выгодно.
- Почему такой балл: в решении всегда есть счётчики `result_details`
  (`correct_picked`, `wrong_picked`, `correct_total`) — они не выдают, какой
  вариант верный. Разбор по каждому варианту (`explanation`: выбран ли,
  верен ли) ученик видит, только когда `show_answer` уже открыл ответ.

**`free_text`**

- `content`: `question`, `max_files` (0–10, по умолчанию 0 — без файлов),
  `min_files` (сколько файлов обязательно), `require_text` (текст обязателен),
  `allowed_mime` (например `["image/jpeg", "image/png"]`, пусто — любые).
  «Обязательно текст и фото»: `require_text: true`, `min_files: 1`.
- `answer_key` — для куратора: `reference` (эталонный ответ), `criteria`
  (критерии), `files` (эталонные файлы с `purpose: answer_key`). Ученику,
  когда `show_answer` разрешает, показывается только `reference`.
- Файлы ученик загружает через `POST /api/files` с `purpose: submission`,
  до 20 МБ каждый.

**`programming`**

- `content`: `statement` (условие), `language: "python3"`, `time_limit_ms`
  (100–15000, по умолчанию 2000), `memory_limit_mb` (16–512, по умолчанию
  256), `template` (заготовка кода), `samples` — открытые примеры
  `{"input", "output"}`, их вывод ученик видит полностью.
- `answer_key`: `test_groups` — группы скрытых тестов `{"name", "points",
  "tests"}`; тест — текстом (`input`, `output`) или файлами (`input_file`,
  `output_file`, загруженные с `purpose: answer_key`: вход до 16 МБ, вывод до
  4 МБ, все файлы задания до 128 МБ); `reference_solution` — эталонное решение.
- `settings.grading`: `tests` (только тесты), `tests_and_review` (тесты, затем
  куратор выставляет итоговый балл), `manual` (только куратор, тесты не
  обязательны).
- `settings.scoring`: `all_or_nothing` (по умолчанию — полный балл, только если
  прошли все тесты) или `per_group` (сумма баллов полностью пройденных групп;
  сумма `points` групп должна равняться `max_score`).
- По скрытым тестам ученик видит только вердикты (`ok`, `wrong_answer`,
  `time_limit`, `runtime_error`, `compilation_error`); правильный ответ после
  `show_answer` — только эталонное решение, тесты никогда.

Новый тип добавляется одним модулем в `backend/src/steps/types/`.

## Оболочка кабинета

После входа навигация и заголовок страницы остаются на месте. Прокручивается
только материал внутри области содержимого. Навигацию можно свернуть до иконок.
Административный заголовок занимает отдельную полосу на всю ширину содержимого.

## Локальная разработка

```bash
cd backend
cp .env.example .env        # заполнить секреты; JUDGE0_AUTH_TOKEN — с сервера
docker compose up -d --build
```

- API: http://localhost:8000 (документация: http://localhost:8000/docs)
- Фронтенд: http://localhost:5173
- Первый администратор:
  `docker compose exec dev uv run --no-sync python src/set_role.py <username> admin`

Код заданий по программированию проверяется на серверном Judge0
(`JUDGE0_URL` в `.env`): локально Judge0 не работает на Docker Desktop,
которому нужен cgroup v1.

### Тесты и линтер

```bash
cd backend
uv sync
uv run pre-commit install                 # один раз: ruff перед каждым коммитом
TEST_DB_URL="postgresql+asyncpg://user:pass@localhost:5432/app_test" uv run pytest
```

Без `TEST_DB_URL` запускаются только юнит-тесты. База из `TEST_DB_URL`
очищается при каждом запуске — не указывайте рабочую.
